## OpenTelemetry Semantic Conventions Zig

Strongly-typed Zig definitions of the [OpenTelemetry semantic conventions](https://github.com/open-telemetry/semantic-conventions):
the agreed-upon naming patterns for attributes, metrics, resources and spans.

The definitions under `src/` are generated from the official specification and
committed, then exposed as the `opentelemetry-semconv` module of the
`opentelemetry-zig` package, wired into the repo build by
`build/semconv/build.zig` (steps: `semconv-test`, `semconv-examples`,
`semconv-docs`, `semconv-generate`).

This module was ported from
[zig-o11y/opentelemetry-semconv](https://github.com/zig-o11y/opentelemetry-semconv).
It has no dependencies beyond the Zig standard library.

The version of the semantic conventions specification targeted here is
**1.36.0**, exposed as `semconv.SCHEMA_URL`.

### Import the package

Fetch the `opentelemetry-zig` repository as a dependency:

```bash
zig fetch --save "git+https://github.com/open-telemetry/opentelemetry-zig"
```

This adds an `opentelemetry` entry to your `build.zig.zon`. Wire the
`opentelemetry-semconv` module into your artifact in `build.zig`:

```zig
const otel = b.dependency("opentelemetry", .{});
exe.root_module.addImport("opentelemetry-semconv", otel.module("opentelemetry-semconv"));
```

Then use the conventions in your code:

```zig
const std = @import("std");
const semconv = @import("opentelemetry-semconv");

pub fn main() !void {
    // Plain attributes carry their metadata directly.
    const status_code = semconv.attribute.http_response_status_code;
    std.debug.assert(std.mem.eql(u8, status_code.name, "http.response.status_code"));
    std.debug.assert(status_code.stability == .stable);

    // Attributes with well-known values have the same shape, and expose the values
    // as a `<name>Value` enum, also reachable as `well_known_values` on the type.
    const method = semconv.attribute.http_request_method;
    std.debug.assert(std.mem.eql(u8, method.name, "http.request.method"));
    std.debug.assert(std.mem.eql(u8, semconv.attribute.http_request_methodValue.get.toString(), "GET"));
    std.debug.assert(@TypeOf(method).well_known_values == semconv.attribute.http_request_methodValue);

    // Metrics carry their instrument type, unit and value type.
    const duration = semconv.metric.http_server_request_duration;
    std.debug.assert(duration.instrument == .histogram);
    std.debug.assert(std.mem.eql(u8, duration.unit, "s"));
}
```

### Namespaces

- `semconv.attribute` — every attribute definition in the registry (generated)
- `semconv.metric` — every metric definition (generated)
- `semconv.resource` — attributes used on resources (generated)
- `semconv.trace` — attributes used on spans and events (generated)
- `semconv.types` — the hand-written types backing all of the above:
  `StringAttribute`, `IntAttribute`, `EnumAttribute`, `Metric`, `StabilityLevel`,
  `RequirementLevel`, `InstrumentType`, and friends

Every definition records its `stability` (`.stable`, `.development`,
`.deprecated`, `.experimental`) and `requirement_level` (`.required`,
`.recommended`, `.opt_in`, `.conditionally_required`), so instrumentation can
filter out conventions that are not yet stable at comptime or runtime.

### Running the tests and examples

From the repo root:

```bash
zig build semconv-test
zig build semconv-examples
```

The examples live in `examples/` and double as executable documentation:

- [examples/basic.zig](examples/basic.zig) — reaching each of the four namespaces
- [examples/advanced.zig](examples/advanced.zig) — filtering by stability and
  requirement level, and working with enum-valued attributes

### Regenerating the definitions

`src/attribute.zig`, `src/metric.zig`, `src/resource.zig`, `src/trace.zig` and
`src/lib.zig` are generated by [Weaver](https://github.com/open-telemetry/weaver)
from the official semantic conventions registry — do not edit them by hand.
Only `src/types.zig` and the templates under
`scripts/templates/registry/zig/` are hand-maintained.

To regenerate (run from the repo root; requires Docker and git):

```bash
zig build semconv-generate
```

The spec version and the Weaver version are both pinned in
[scripts/generate-consts-from-spec.sh](scripts/generate-consts-from-spec.sh).
To move to a newer specification release, bump `SPEC_VERSION` there, rerun the
step, and commit the regenerated `src/`. The script keeps `SCHEMA_URL` in sync
with the spec version via the `schema_url` parameter in
[scripts/templates/registry/zig/weaver.yaml](scripts/templates/registry/zig/weaver.yaml).
